# E4 报告（中文摘要）：harness v0.5 在新零售题上的检验

英文全文见 [REPORT.md](REPORT.md)，数字以英文版为准。

- **运行：** 2026-11-07 09:05 至 12:09（CST），共 816 次尝试，全部完成。组成是 2 个 agent × 2 组（N、H）× 68 道新题 × 每题 3 次。
- **预注册：** 方案见 [PREREGISTRATION.md](PREREGISTRATION.md)，09:02 定稿。之后只加了敏感性分析脚本，加的时间在读任何结果之前，记在 [DEVIATIONS.md](DEVIATIONS.md)。
- **分析：** 用冻结的 `analyze.py --rules e4` 跑。

## 结论

**四条判定规则没有一条支持 harness。**

| 规则 | 结果 | 数字 |
|---|---|---|
| R1：H 组错答案更少，且误拦 ≤ 15% | 未达成 | 静默错误 H 2.2% 对 N 1.7%，配对差 [−2.7, +4.4] 个百分点；误拦 23.3% |
| R2：误拦 > 15%（仍然太严） | **达成** | 23.3% [13.7, 33.2]（E3a 是 26.5%，题库不同） |
| R3：直接题上 H 组错得更少 | 未达成 | 两组都是 2.9% |
| R4：门禁加第二意见和两个 agent 一样安全、拦得不更多、跑得更少 | 未达成 | 静默错误 2.2% 对 0.0%；误拦 6.6% 对 2.2%；每次尝试跑 1.18 次 |

预注册的敏感性分析（去掉嵌套题，或者去掉和 E3a 最接近的两题）四条判定都不变。

1. **不用 harness，两个 agent 在这些题上几乎都答对了。** 正确率 98.3%（Claude 98.5%，Codex 98.0%），留给门禁去抓的错误很少。
   - N 组的 7 次静默错误是读错题，以及退款或时间窗口出错。
   - 其中 1 次数值正确，只是月份写成了英文名，评分器读不了。
2. **H 组的 9 次静默错误全部是 harness 造成的。** 这 9 次都出在四道写着“产品销售额”的题上。
   - 门禁把“销售额”这个通用词读成了净销售额，于是把 agent 原本正确的 gross 答案当成“没有回答所问的问题”拦下。
   - agent 改成 net 以后，门禁核验通过，错答案就交付了。
   - 同样这几道题，N 组 24 次全对。
   - 问题出在 `src/dsharness/tools/analytics.py:497-499`：通用词给出的默认读法被当成了明确读法（F23 只做了一半）。
3. **误拦大多是 harness 自己的缺口，不是 agent 的错。** 92 个正确答案被拦，全部集中在 18 道题上，原因有六类，其中五类是 harness 或接入时的缺口（见下表）。其余 49 道题，H 组 294 次尝试有 293 次正确交付，没有拦下一个正确答案。
4. **用 harness，每个正确交付的答案贵 3–5 倍。** Claude 是 $0.056 对 $0.018；Codex 是 508k 对 93k tokens。中位用时 Claude 18.7 秒对 10.5 秒，Codex 39.5 秒对 24.8 秒。

**含义：** 在干净、有治理的零售数据上，强 agent 加一份好的数据目录，回答单个分析问题时用不着这个门禁；门禁的术语检查还可能帮倒忙。harness 的价值要在别的工作上证明：管道（E3d）、会变化的数据，以及流程错误。

## 误拦原因（事后归因，设计者逐题判断）

| 原因 | 题数 | 拦下的正确答案 | H 静默错误 | N 静默错误 | 修法 |
|---|---|---|---|---|---|
| “产品销售额”被读成净额 | 4 | 13 | 9 | 0 | 只来自通用词的读法，被一个能压过它的声明指标满足 |
| 净额被定义为“毛额减取消额” | 3 | 15 | 0 | 0 | 定义里提到的另一个指标是在解释它，不是替换它 |
| 逐月同比 | 4 | 23 | 0 | 2 | 加一个带基期偏移（12 个月或 1 个月）的逐月变化步骤 |
| “2025 年 1 至 11 月”被读成全年 | 2 | 11 | 0 | 0 | 把“某年某月至某月”解析成一个区间 |
| 维度值没识别出来（物料编码、排除条件） | 2 | 11 | 0 | 3 | 识别物料编码后面的商品编码；排除条件里的值是被排除，不是被点名 |
| 指标短语缺失或读错 | 3 | 18 | 0 | 0 | 用这些说法做术语覆盖测试 |
| 最终答案不是核验过的行 | 1 | 1 | 0 | 0 | 无（agent 的问题） |

- O3 估计新题里有 7% 会被读成别的指标；实际是 10 道题（15%）。这 10 道题造成了 92 次误拦中的 46 次，以及 H 组全部 9 次静默错误。
- **带理由的暂缓，本身就是一条指令。** 有 9 次尝试，门禁的提示（“题目问的是净额……”）把 agent 从正确答案推到了错误答案。门禁对术语读法没有把握时，应该去问人，而不是让 agent 重新作答。
- **报告脚本的缺口：** `hold_reasons.py` 没读 harness 记下的矛盾说明，导致 64 次暂缓显示“没有记录原因”。已补上，属于探索性输出，不影响任何判定数字。

## 标注

- 设计者标注了全部 20 次错答，在看 Haiku 的盲标之前完成。和 Haiku 一致 5/6，κ 0.727。
- H 组的 13 次错答里，有 11 次是 harness 造成的，9 次静默错误全在其中。
- N 组 7 次：读错题 3、退款 2、时间 1、格式 1。

## 下一步

1. **不在这个题库上继续调 v0.5。** 上面的修法是在 E4 的题上找到的，要换新题库才能检验。更要紧的是，agent 单独作答已经到 98%：这类任务里，任何门禁最多只能减少约 1.7 个百分点的静默错误，代价是 3–5 倍的成本。
2. **先修伤害。** 通用词读法的矛盾改成问人，不再用暂缓去引导 agent 改答案（F23）。这是正确性修复，和 E4 本身无关。
3. **把 harness 的检验转到错误多或代价大的地方：** 管道和会变化的数据（E3d：schema 漂移、控制总数、应当暂缓的 2026-09）；建模和实验读数（E3b、E3c，用完整工具链）；长的多步骤工作，那里一步出错会层层放大。

## 局限

- 一个零售仓库、两个 agent、一个时期。题是新写的，但出题模型和答题 agent 是同两个模型家族。
- 误拦原因是设计者的事后判断；Haiku 只核对了错误标注（20 次中的 6 次），没有核对原因。
- 68 道题的区间很宽：配对静默错误差从 −2.7 到 +4.4 个百分点。
- N 组拿到的数据目录写得好，含官方定义。目录差一些的话，N 组可能错得更多。
