## E-8 经济与采纳

- **〔E-8.1〕** [verified; July-Aug 2025] MIT NANDA's 'GenAI Divide' (2025) is a small, mostly self-reported study. Its '95%' means 95% of organizations report no measurable P&L impact from integrated or custom GenAI pilots. It does not mean 95% of AI projects fail. Generic chat tools convert well; custom enterprise tools mostly do not.  
  来源：<https://mlq.ai/media/quarterly_decks/v0.1_State_of_AI_in_Business_2025_Report.pdf> <https://finance.yahoo.com/news/mit-report-95-generative-ai-105412686.html> <https://www.fortune.com/2025/08/19/shadow-ai-economy-mit-study-genai-divide-llm-chatbots>
- **〔E-8.2〕** [verified; Aug-Oct 2025] Critiques of the MIT report are valid. The sample is small and drawn from conferences, success is self-defined, and the report contradicts itself on budgets. Larger surveys find mostly positive self-reported ROI. The direction of the finding (pilots stall) is supported; the exact number is not.  
  来源：<https://mlq.ai/media/quarterly_decks/v0.1_State_of_AI_in_Business_2025_Report.pdf> <https://customerthink.com/the-great-genai-divide-debunking-the-myth-of-95-failure/> <https://knowledge.wharton.upenn.edu/special-report/2025-ai-adoption-report>
- **〔E-8.3〕** [verified; July 2025] In the MIT data, the clearest ROI came from replacing external spend in back-office work (BPO contracts, agencies, outsourced risk checks), not from cutting internal staff.  
  来源：<https://mlq.ai/media/quarterly_decks/v0.1_State_of_AI_in_Business_2025_Report.pdf>

- **〔E-5.22〕** [verified; 2026-10] Across vendors, the agent stack has converged on the same parts: (1) a business-user chat or 'coworker' over a governed semantic layer, (2) an in-platform coding agent for SQL, Python, pipelines and ML, (3) a managed MCP server plus third-party MCP connectors, (4) a managed sandbox for running agent-written code, (5) agent identity, audit and budgets, and (6) token or credit consumption pricing, often with temporary free promotions. ## E-4 基准与可靠性

- **〔E-4.1〕** [verified; 2026-10-19 (leaderboard fetched)] Spider 2.0 leaderboard (Oct 2026). Snow top score is 96.70 (Genloop Sentinel Agent v2 Pro). Lite top is 76.23 (Tencent Tianqiong Data Agent + GLM 5.2). DBT top is 65.6 (SignalPilot). Most GPT-5-class Spider2-DBT agents score 35-41. Five of the top-10 Snow entries come from China-based teams (DAQUV, Tencent, ByteDance). Paytm, an Indian firm, is also in the top 10.  
  来源：<https://spider2-sql.github.io/> <https://raw.githubusercontent.com/xlang-ai/Spider2/main/README.md>
- **〔E-4.2〕** [likely; 2026-01-19] Headline text-to-SQL leaderboard numbers are partly measuring benchmark artifacts. A PVLDB audit found 62.8% annotation errors in Spider 2.0-Snow (121 examples with public gold SQL) and 52.8% in BIRD Mini-Dev. Spider2 has also published all examples and gold answers for self-evaluation since 2024-12-24. Snow scores above 90% therefore probably reflect fitting to the gold answers' conventions, not real enterprise accuracy.  
  来源：<https://arxiv.org/abs/2601.08778> <https://raw.githubusercontent.com/xlang-ai/Spider2/main/README.md>
- **〔E-4.3〕** [verified; 2026-09] On BIRD, single-turn text-to-SQL on curated public databases has reached about 80-83% test execution accuracy. Humans score 92.96. The main gains came from generating many candidates and selecting among them. Selection is now the bottleneck: the best candidate is often in the pool but is not picked.  
  来源：<https://bird-bench.github.io/> <https://arxiv.org/abs/2410.01943v1> <https://arxiv.org/pdf/2509.24403>
- **〔E-4.4〕** [verified; 2026-05] Accuracy collapses once tasks become ambiguous and interactive, or use real enterprise warehouses. On BIRD-Interact (ICLR 2026 Oral), GPT-5 completes 8.67% of tasks in the conversational setting (c-Interact) and 17.00% in the agentic setting (a-Interact). On BEAVER, built from private enterprise warehouses, state-of-the-art agentic frameworks with GPT-5.2 reach 10.8% execution accuracy, and 30.1% even with oracle subtask hints.  
  来源：<https://arxiv.org/abs/2510.05318> <https://bird-interact.github.io/> <https://bird-bench.github.io/>
- **〔E-4.5〕** [verified; 2026-10-19 (Gradio config fetched)] DABstep (Adyen/Hugging Face, 450 multi-step financial-analysis questions). Hard-split accuracy on the validated leaderboard rose from 14.55% at launch to 89.95%. The winning recipe was an offline, curated, reusable function library, not a bigger model at inference. Validation is now closed: the unvalidated board is full of 100% entries, including ones named 'test gold' and 'Spoofer'. DABStep-v2 is pending.  
  来源：<https://huggingface.co/spaces/adyen/DABstep> <https://huggingface.co/blog/nvidia/nemo-agent-toolkit-data-explorer-dabstep-1st-place> <https://arxiv.org/abs/2506.23719>
- **〔E-4.6〕** [verified; 2026-03 (leaderboard frozen)] On MLE-bench (75 Kaggle competitions, 24h budget), top agents now medal on about 61-64% of all competitions and 77-80% of the Low/Lite split (22 competitions). High-complexity competitions sit at about 40-47%. The official leaderboard has stopped taking new submissions, and v1 has known dataset issues.  
  来源：<https://github.com/openai/mle-bench>
- **〔E-4.7〕** [verified; 2026-09] End-to-end data-lake pipelines remain a weak spot. On KramaBench (ICLR 2026), the best system reaches 55% end-to-end, and only 62% even with perfect retrieval. LLMs identify up to 42% of the important data tasks but fully implement only 20% of individual subtasks. A later auditable runtime (RADAR) reports 0.723 overall.  
  来源：<https://arxiv.org/abs/2506.06541> <https://arxiv.org/abs/2609.32528>
- **〔E-4.8〕** [verified; 2026-08-06] Data engineering (ELT/dbt) has split in two: extraction and loading are largely solved, but transformation and modeling are not. Repeat-run consistency (Pass^3) sits 8-16 points below Pass@1, which matters for production pipelines.  
  来源：<https://arxiv.org/html/2603.29399v2> <https://arxiv.org/pdf/2504.04808> <https://www.snowflake.com/en/blog/engineering/data-eng-bench-data-engineering-agent-benchmark/>
- **〔E-4.9〕** [likely; 2026-04] ADE-bench (dbt Labs with Benn Stancil, Apr 2026) found that context and configuration mattered more than model choice. Agents fix syntax and logic bugs well. They struggle with data-level problems (bad values, wrong filter strings, inconsistent entity states) unless they actually query the data. Early wrong turns compound.  
  来源：<https://docs.getdbt.com/blog/building-a-better-data-agent-benchmark> <https://www.paradime.io/blog/dinoai-ade-benchmark-report>
- **〔E-4.10〕** [verified; 2026-10] Older data-science agent benchmarks (2024-25 models) put realistic multi-step analysis accuracy at about 30-35%. ScienceAgentBench has plateaued at about 30-33% even with 2025 frontier models, and the scaffold changes results more than the model does.  
  来源：<https://arxiv.org/abs/2409.07703> <https://aclanthology.org/2024.emnlp-main.748> <https://hal.cs.princeton.edu/scienceagentbench>
- **〔E-4.11〕** [verified; 2026-04] Curated semantics (a semantic layer, knowledge graph or metric definitions) consistently adds about 8-25 points of text-to-SQL accuracy. Its biggest value is turning plausible wrong answers into explicit 'cannot answer' errors. The independent effect size at moderate scale is about +20 points, not the 3-5x that vendors claim.  
  来源：<https://docs.getdbt.com/blog/semantic-layer-vs-text-to-sql-2026> <https://arxiv.org/abs/2604.25149> <https://arxiv.org/abs/2405.11706>
- **〔E-4.12〕** [verified; 2026-08] Retrieving historical-query context (SQL 'reference cards') gives only small, statistically insignificant gains on the public enterprise benchmark (BEAVER). The gains were larger on an in-house production set. Context engineering does not substitute for curated semantics.  
  来源：<https://arxiv.org/abs/2608.22830>
- **〔E-4.13〕** [verified; 2026-09] Most data-agent failures are silent: the agent returns a normal-looking but wrong answer rather than crashing. Iterative self-verification does not eliminate this. An auditable runtime with typed operators and runtime validation reduced silent errors by 28.6%.  
  来源：<https://arxiv.org/html/2609.32528> <https://arxiv.org/abs/2609.37153> <https://arxiv.org/abs/2604.25345>
- **〔E-4.14〕** [verified; 2026] LLM-as-judge without running the code is unreliable for verifying code and SQL. The best code judge reaches about 82%. Accuracy swings by up to 14% when the order of the two responses is swapped. Pairwise judging clearly beats pointwise scoring. Execution-match metrics also have material false positives and negatives.  
  来源：<https://arxiv.org/abs/2507.10535> <https://arxiv.org/html/2507.10535v2> <https://arxiv.org/abs/2409.19014v1>
- **〔E-4.15〕** [verified; 2026-06] Verifiers that interact with the execution environment measurably beat text-only verifiers on data tasks. DataPRM (KDD 2026), a 4B process reward model that probes intermediate execution states, finds silent errors that general reward models miss. It improves best-of-N results on ScienceAgentBench and DABStep.  
  来源：<https://arxiv.org/abs/2604.24198>
- **〔E-4.16〕** [verified; 2025-12] In multi-agent setups, majority voting provides most of the gain usually credited to debate. Vanilla debate does not improve expected correctness. Consensus-based selectors can also agree on the same hallucination.  
  来源：<https://arxiv.org/abs/2508.17536> <https://neurips.cc/virtual/2025/poster/116557> <https://preview.aclanthology.org/ingest-acl/2026.acl-long.313/>
- **〔E-4.17〕** [verified; 2026] Reliability is lagging accuracy. In HAL's study of 14 models across 24 months, accuracy kept rising while reliability (consistency across runs, robustness to paraphrased prompts, predictability) improved only slightly. The gap between 'solves it at least once' (pass@k) and 'solves it every time' (pass^k) is substantial for every model.  
  来源：<https://hal.cs.princeton.edu/reliability/findings> <https://arxiv.org/abs/2602.16666> <https://www.snowflake.com/en/blog/engineering/data-eng-bench-data-engineering-agent-benchmark/>
- **〔E-4.18〕** [verified; 2026-10] Benchmark answer keys are themselves a major error source, and errors cut in both directions. Fixing ELT-Bench added about 10 pp. BIRD and Spider2 annotation errors reshuffle rankings. MLE-bench v1 has leakage. DABstep's open board was gamed. Any in-house evaluation set needs its own audit step.  
  来源：<https://arxiv.org/html/2603.29399v2> <https://arxiv.org/abs/2601.08778> <https://github.com/openai/mle-bench>

## E-6 Agent 工具链

- **〔E-6.1〕** [verified; 2026-07-28 spec; checked 2026-10-19] The current MCP revision is 2026-07-28. It makes the protocol stateless: protocol-level sessions, the Mcp-Session-Id header and the initialize handshake are gone. Every request carries its protocol version and client capabilities in _meta, and servers must implement server/discover.  
  来源：<https://modelcontextprotocol.io/specification/2026-07-28/changelog> <https://modelcontextprotocol.io/specification/versioning> <https://aaif.io/blog/mcp-2026-changes-the-rules>
- **〔E-6.2〕** [verified; 2026-07-28] Remote MCP authorization is now a full OAuth 2.1 resource-server profile. Servers MUST publish Protected Resource Metadata (RFC 9728). Clients MUST send RFC 8707 resource indicators, MUST validate the RFC 9207 iss parameter when it is present, and MUST NOT pass tokens through. Client ID Metadata Documents are preferred, Dynamic Client Registration is deprecated, and STDIO servers should take credentials from the environment instead.  
  来源：<https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization>
- **〔E-6.3〕** [verified; 2026-06-18] The Enterprise-Managed Authorization (EMA) extension for MCP became stable on 2026-06-18. An admin provisions MCP server access through the corporate IdP: the client gets an ID-JAG token at SSO and exchanges it for an access token, so users never see a per-server consent screen.  
  来源：<https://blog.modelcontextprotocol.io/posts/enterprise-managed-auth/> <https://modelcontextprotocol.io/extensions/auth/enterprise-managed-authorization>
- **〔E-6.4〕** [verified; 2026-08-17] The protocols are now governed neutrally. The Linux Foundation formed the Agentic AI Foundation (AAIF) on 2025-12-09 with MCP, goose and AGENTS.md as its first projects. A2A joined AAIF on 2026-08-17. AAIF's project list in August 2026 was AGENTS.md, goose, MCP, agentgateway and A2A. Agent Skills was not on it; it is still an Anthropic-originated open standard developed on its own GitHub.  
  来源：<https://www.linuxfoundation.org/press/linux-foundation-announces-the-formation-of-the-agentic-ai-foundation> <https://aaif.io/blog/a2a-joins-aaif> <https://agentskills.io/home>
- **〔E-6.5〕** [verified; 2026-10-19] The stable A2A line is v1.0.x: v1.0.0 was released on 2026-03-12 and v1.0.1 on 2026-05-28. Blog claims of an 'A2A v1.2' could not be confirmed from any primary source. A2A is positioned as agent-to-agent (opaque agents, task delegation), complementing MCP, which is agent-to-tool.  
  来源：<https://github.com/a2aproject/A2A/releases> <https://a2a-protocol.org/latest/> <https://linuxfoundation.org/press/a2a-protocol-surpasses-150-organizations-lands-in-major-cloud-platforms-and-sees-enterprise-production-use-in-first-year>
- **〔E-6.6〕** [verified; 2026-10-19] Agent Skills (a folder with a SKILL.md file plus optional scripts, references and assets, loaded by progressive disclosure) is the de facto cross-vendor way to package procedures. The official client list includes several data platforms and Chinese tools.  
  来源：<https://agentskills.io/home> <https://developers.openai.com/codex/skills>
- **〔E-6.7〕** [verified; 2026-10-19] AGENTS.md is the cross-agent standard for repo instructions: the nearest file wins and an explicit user prompt overrides it. Claude Code now reads AGENTS.md as well as CLAUDE.md, so one instruction file can serve all three major CLIs.  
  来源：<https://agents.md/> <https://code.claude.com/docs/en/memory.md>
- **〔E-6.8〕** [verified; 2026-10-18] Claude Code headless mode (claude -p) is now framed as the Agent SDK CLI and is ready for CI. --bare skips auto-loading hooks, skills, plugins, MCP servers and CLAUDE.md, and will become the default for -p. The CLI offers JSON-schema structured output, cost reporting and budget caps. Security caveat: without --bare, -p runs a repo's hooks and .mcp.json servers with no trust dialog.  
  来源：<https://code.claude.com/docs/en/headless> <https://github.com/anthropics/claude-code/releases>
- **〔E-6.9〕** [verified; 2026-10-19] Claude Code's extension model separates concerns cleanly:
- CLAUDE.md: always-on, kept under 200 lines.
- Skills: only the description loads until a skill is used.
- MCP: tool search on by default, so full schemas are deferred.
- Subagents: isolated context that returns a summary.
- Hooks: deterministic and outside the context window.
- Plugins: the distribution unit.
Anthropic's guidance is to put guardrails in hooks rather than prompts.  
  来源：<https://code.claude.com/docs/en/features-overview.md> <https://code.claude.com/docs/en/agents.md>
- **〔E-6.10〕** [verified; 2026-10-15] Anthropic now offers three harness options:
- Claude Agent SDK (Python and TypeScript): the Claude Code loop as a library you run yourself.
- Claude Managed Agents (beta, header managed-agents-2026-04-01): hosted loop with an Anthropic cloud sandbox or a self-hosted sandbox.
- Raw Messages API: you write the loop.
Managed Agents and programmatic tool calling are NOT eligible for Zero Data Retention.  
  来源：<https://code.claude.com/docs/en/agent-sdk/overview> <https://platform.claude.com/docs/en/managed-agents/overview> <https://platform.claude.com/docs/en/agents-and-tools/tool-use/programmatic-tool-calling>
- **〔E-6.11〕** [verified; 2026-10-15] OpenAI's Agents SDK (announced 2026-04-15, 'The next evolution of the Agents SDK') adds a model-native harness and native sandbox execution.
